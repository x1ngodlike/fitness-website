# 健康星球 - 群健康挑战赛 产品需求文档

## 1. 产品概述

**健康星球** 是一个健身爱好者之间的挑战激励平台。发起挑战，设置"通赔金额"和"底仓金额"作为筹码，参与者选择"白（支持挑战者成功）"或"黑（反对挑战者成功）"来加入挑战。通过筹码机制互相激励，克服惰性，共同进步。

- 产品定位：朋友圈/小团队的健身激励工具
- 目标用户：健身爱好者、想要养成运动习惯的人群、互相监督的健身小组

## 2. 用户角色与权限

| 角色 | 说明 | 权限 |
|------|------|------|
| 管理员 | 平台运营者，通过密码登录 | 查看全部挑战、创建挑战、编辑挑战、封档/解封、确认结果、编辑参与者、切换环境模式 |
| 普通用户 | 浏览/参与挑战 | 浏览首页挑战卡片、查看挑战详情、参与挑战（押钱选边） |

## 3. 核心功能模块

### 3.1 首页（/）

| 参与区（进行中 + 未封档 + 未过期） | 姓名输入、金额输入、选择白/黑、立即参与按钮 |

| 结算信息区（已结束） | 挑战者结果、赢家总数、总奖池、分配说明 |
| 管理员操作区 | 编辑挑战、封档/解除封档、标记挑战者成功/失败 |

| 模块 | 功能描述 |
|------|----------|
| 权限校验 | 非管理员显示登录提示，管理员显示完整表单 |

## 4. 核心概念与业务规则

### 4.1 挑战状态

| 状态 | 条件 | 说明 |
|------|------|------|
| 进行中 (active) | status === 'active' 且 未过期 | 参与者可以加入 |
| 待确认 (pending) | status === 'active' 但已过期 | 需要管理员确认结果，不可加入 |
| 已结束 (completed) | status === 'completed' | 已有胜负结果，展示结算信息 |

### 4.2 封档（isBlocked）

- 仅在"进行中"状态下有效
- 封档后普通用户看到"挑战已封档"提示，不能参与
- 管理员仍可在管理面板编辑参与者和挑战信息
- 首页卡片显示"封档"红色半透明标签

### 4.3 参与者选边规则

- **白（support）**：押挑战者能成功
- **黑（oppose）**：押挑战者会失败
- 每人可多次参与（每次生成新的 participant 记录）
- 参与金额自定义（无最低限制）

### 4.4 结算规则

管理员点击"标记挑战者成功/失败"时，所有参与者自动结算：

| 挑战者结果 | 白方（support） | 黑方（oppose） |
|-----------|----------------|----------------|
| 成功 ('success') | win | lose |
| 失败 ('failed') | lose | win |

**奖金计算（详情页实时计算展示）**：
- 赢家按各自押注比例分配输家押金总额
- 挑战失败时发起人付出 = max(底仓金额, min(赢家押注 - 输家押金, 通赔金额))
- 总奖池 = 输家押金 + 发起人付出

### 4.5 环境模式

| 模式 | 说明 | 数据来源 | 持久化 |
|------|------|---------|--------|
| 测试环境 (test) | 开发/演示用 | mockData.ts（10条示例数据） | 不持久化 |
| 正式环境 (production) | 真实使用 | localStorage（key: challenge-production-v1） | 所有增删改操作持久化 |

管理员可在导航栏切换环境模式，该选择持久化保存。

## 5. 数据模型

### 5.1 挑战 (Challenge)

| 字段 | 类型 | 描述 |
|------|------|------|
| id | string | 唯一标识符（挑战创建时生成） |
| theme | string | 挑战主题 |
| goal | string | 挑战目标描述 |
| hostName | string | 挑战者/发起人姓名 |
| coverImage | string | 封面图片URL或base64 |
| startDate | string | 开始日期 (YYYY-MM-DD) |
| endDate | string | 结束日期 (YYYY-MM-DD) |
| maxPayout | number | 通赔金额（失败赔付上限） |
| minStake | number | 底仓金额（失败最少赔付） |
| status | 'active' \| 'pending' \| 'completed' | 挑战状态 |
| isBlocked | boolean | 是否封档（禁止参与） |
| participants | Participant[] | 参与者列表 |
| createdAt | number | 创建时间戳 |

### 5.2 参与者 (Participant)

| 字段 | 类型 | 描述 |
|------|------|------|
| id | string | 唯一标识符 |
| challengeId | string | 所属挑战ID |
| participantName | string | 参与者姓名 |
| stake | number | 押注金额 |
| side | 'support' \| 'oppose' | 白/黑选边 |
| result | 'win' \| 'lose' \| 'pending' | 结算结果 |
| createdAt | number | 参与时间戳 |

### 5.3 应用状态（Meta）

| 字段 | 类型 | 描述 |
|------|------|------|

## 6. 用户界面设计

### 6.1 设计风格
- **整体风格**：深色运动科技风，能量感和竞技感
- **色调**：深黑背景 + 活力橙强调色 + 白色文字
- **布局**：卡片式布局，信息层次分明
- **动效**：卡片淡入入场、hover交互

### 6.2 配色方案

| 用途 | 颜色（Tailwind） |
|------|-----------------|
| 主背景 | bg-neutral-950 (#0D0D0D) |
| 卡片背景 | bg-neutral-900 (#171717) |
| 强调色 | 渐变 from-orange-500 to-orange-600 |
| 成功标签 | bg-green-500 实心 + 白色文字 |
| 待确认标签 | bg-yellow-500 实心 + 白色文字 |
| 已结束标签 | bg-neutral-600 实心 + 白色文字 |
| 封档标签 | bg-red-500/10 半透明 + 红色文字 + 红色边框 |

### 6.3 字体与排版
- 主标题：text-4xl / md:text-5xl, font-bold
- 卡片标题：text-lg, font-bold
- 正文：text-sm
- 标签：text-xs, font-medium

### 6.4 响应式设计
- 桌面端优先设计（grid cols: 1→2→3）
- 平板和手机自适应布局
- 触摸友好的按钮尺寸

## 7. 关键流程

### 7.1 挑战创建流程

1. 管理员登录
2. 进入"创建挑战"页面
3. 填写表单（封面、主题、目标、发起人、时间、通赔、底仓）
4. 提交后生成 Challenge 对象，写入 localStorage（正式环境）
5. 跳转首页

### 7.2 挑战参与流程

1. 用户在首页点击挑战卡片进入详情
2. 填写姓名、押注金额、选择白/黑
3. 提交后生成 Participant 对象并追加到挑战的 participants 数组
4. 持久化后立即在详情页看到自己的参与记录

### 7.3 结算流程

1. 管理员进入管理面板或详情页
2. 点击"标记挑战者成功"或"标记挑战者失败"
3. 系统遍历参与者，根据规则更新 result 字段
4. challenge.status 更新为 'completed'
5. 持久化后详情页展示结算信息和赢家奖金

## 8. 非功能性需求

- **数据持久化**：正式环境所有操作写入 localStorage（key: challenge-meta-v1, challenge-production-v1）
- **环境隔离**：测试环境与正式环境数据互不干扰
- **响应式**：桌面/平板/手机均可正常使用
- **无后端依赖**：纯前端实现，数据完全本地存储
