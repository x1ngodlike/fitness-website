## Git 推送认证坑（重要，已踩）
- 仓库 `x1ngodlike/fitness-website`（owner=x1ngodlike，个人 User，无组织 SSO）。
- **fine-grained 令牌（`github_pat_` 前缀）不能用于 Git over HTTPS 推送**，只能走 API（Bearer）。现象：API `GET /repos/...` 返回 `permissions.push=True`，但 `git push`（Basic 或 extraHeader Bearer）一律失败——Basic 返回 403 "Permission denied"，Bearer 因本机 GCM askpass 无 TTY 卡在 `could not read Username`。
- **解决办法**：推送必须用 **Classic 经典令牌（`ghp_` 前缀）+ `repo` 范围**，走 Basic 认证（URL 内联 `https://user:ghp_xxx@github.com/...` 或 `GIT_TERMINAL_PROMPT=0`）。或让用户本机 `git push`（GCM 弹浏览器登录）。
- 本机 git 身份缺失：已 `git config user.name "x1n" / user.email "593587956@qq.com"`（沿用历史提交身份）。
- 注意 `.gitignore` 的 `data/` 规则会误伤 `src/data/`，导致已追踪的 `src/data/mockData.ts` 无法普通 `git add`，需 `git add -f`（仅针对已追踪文件，安全）。

## Docker 构建失败根因（UNRAID 部署，已踩 + 已修）
- 症状：`docker build` 在 `npx vite build` 阶段报 `Could not resolve "../data/placeholderImages" from "src/pages/CreateChallengePage.tsx"`（rollup `handleInvalidResolvedId`）。
- 双重根因：
  1. `.dockerignore` 里裸 `data/` 会匹配**任意层级** `data/`，把 `src/data/` 整个排除出构建上下文 → 容器内 `src/data/*` 全部缺失。
  2. `.gitignore` 里同为裸 `data/`，导致 `src/data/placeholderImages.ts` **从未被 git 追踪**（连 untracked 都不显示），git clone 部署时该文件天然缺失。
- 本地 Windows 能 build 过，是因为文件在磁盘上存在、且 Windows 大小写/忽略不敏感；容器是 Linux，.dockerignore 生效即炸。
- 修复（commit `66b493a`）：`.gitignore` 与 `.dockerignore` 的 `data/` 都改为根锚定 `/data/`（仅排除项目根 data/，不碰 src/data/）；并把被忽略的 `placeholderImages.ts` 补 `git add` 提交进仓库。
- 部署同步要点：UNRAID 上若 `.dockerignore` 仍是旧 `data/`，或 clone 的仓库缺 `placeholderImages.ts`，构建仍会挂。端到端正确做法 = 把 `66b493a` 推到 GitHub → UNRAID `git pull` → `./deploy/build.sh`。临时绕过 = UNRAID 上直接删 `.dockerignore` 的 `data/` 行并确保 `src/data/placeholderImages.ts` 存在后重建。
- 当前未推送提交仅剩 `66b493a`（用户本机 `git push origin main` 即可，其 GCM 正常）。
